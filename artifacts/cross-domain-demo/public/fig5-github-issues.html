Bug Report — CorrelationEngine False Positives

Summary: During TC-03 seed validation the CorrelationEngine is generating CorrelatedAlert objects for event clusters where all events originate from a single domainId. This violates the cross-domain constraint that is central to the SIEM's detection model.

Steps to Reproduce

  • Run the simulator at 10 evt/s/domain for 60 seconds
  • Observe CorrelatedView — alerts appear with domains.length === 1
  • Filter alert log by domainId === "ALPHA" — same-domain clusters match

Root Cause

Over-weighting of the temporal proximity factor in computeConfidence() causes single-domain bursts to breach the 0.75 threshold before the domain-count guard in tryCorrelate() can reject them.

Module: src/lib/simulation.ts · tryCorrelate() · line 183
Guard: uniqueDomains.length < 2 → return null ← missing in v1.1.0
Environment: React 18 / TypeScript 5.9 / Chrome 124

Expected Behaviour

tryCorrelate() must return null for any event cluster where uniqueDomains.length < 2.

Fix

Introduce explicit domain-exclusion guard at line 183 and recalibrate temporal weighting coefficients. Resolved in PR #3 — merged to main, tagged v1.2.0.
